# 设计基线原则（本文件自身亦受本原则约束，修订须走 CP）


## 第一部分：落盘基线不可变，修订必须版本化

X.1 单一事实源：一切权威状态必须以文件落盘。会话记忆、内存状态、未落盘的中间结论不构成事实。
X.2 基线化：文件经批准落盘为版本对象后不可变。基线化之前的草稿区文件不受约束。
X.3 禁止原地修订：禁止修改、覆盖、截断、删除任何已基线内容；禁止"先改原文、后补记录"；
    禁止改写已发布历史。一切基线化必须有人工批准凭证。
X.4 修订即新版本：修订产生 V(n+1)，与 V(n) 并存，记录 parent、CP、哈希、时间。
X.5 生效即指针切换：当前版由 manifest 指针定义，修订通过原子切换指针生效，切换留痕。
X.6 废弃即标记：删除与替换以状态表达，版本对象物理保留，任意历史状态可复现。
X.7 豁免区：草稿（未基线路径）、manifest 指针、可重建派生产物（trace/graph、pending、索引）、
    append-only 日志（trace/ledger 只许追加）、代码与工具（由 VCS 版本化，禁止 force-push）。
X.8 可执行校验：每个基线版本登记 sha256；钩子与 CI 校验对象哈希不变、parent 合法、指针有效，
    违规即阻断。
X.9 生成与存储解耦：修订可由增量编辑指令生成，由工具合成新版本落盘。本原则约束存储语义，
    不要求整篇重写。


## 第二部分：事实单源，叙述引用

Y.1 跨文档共享的事实（需求、角色、字段、规则）只存于 design/facts/，每个事实一个稳定 ID，
    ID 永不复用。
Y.2 叙述文档以 ID 引用事实，禁止复制事实内容。纯复述性段落应由事实渲染生成。
Y.3 生成中新发现的事实进 design/inbox/，经 CP 入 facts 后方可被引用；禁止写入散文即视为事实。
Y.4 下游文档必须钉住上游版本（based_on: ID@vN）；引用事实用裸 ID（uses_facts）。
Y.5 有意省略必须显式声明（omits: fact + reason），未声明的缺失即为缺陷。


## 第三部分：不一致允许存在，但必须可见、有界、可收敛

Z.1 任一时刻，任何跨文档差异只能处于四态之一：
    omits（显式省略）/ suspect（待核销疑点）/ CP（待批准提案）/ waiver（有期限豁免）。
    四者之外发现差异，即为流程缺陷，须报告，禁止静默修补。
Z.2 内容只读，状态外置：一致性结论写入 trace/ledger.jsonl，不触碰内容层。
Z.3 检查随变更传播：上游修订后只对可达下游标记疑点；核对结论按内容哈希缓存，
    内容未变的配对永不重查。禁止常态化全量语义审查。
Z.4 提案按根因批量：一次批准覆盖同一根因的全部受影响文件，原子生效。
Z.5 草稿最终一致，基线严格一致：门禁处要求 L0/L1 全绿且疑点清零或全部豁免。
Z.6 豁免须有负责人与到期日，作为显式设计债定期清偿。
